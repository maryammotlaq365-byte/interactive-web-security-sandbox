Negative Quantity

Learn how a business logic flaw lets attackers manipulate shopping cart totals using negative quantities.

01. What is Negative Quantity?

Negative Quantity is a business logic flaw that occurs when an application accepts negative product quantities without proper validation. An attacker may manipulate shopping cart calculations and cause incorrect prices or unauthorized financial benefits.

OWASP: A04:2021 – Insecure Design

CWE: CWE-1284 – Improper Validation of Specified Quantity in Input

02. The Vulnerable Code

This check blocks zero but allows negative quantities, which can reduce the cart total. 

function addToCart() {
    const inputValue = quantityInput.value.trim();
    const quantity = Number(inputValue);

    if (inputValue === "" || !Number.isInteger(quantity)) return;
    if (quantity === 0) return;

    cartQuantity += quantity;
    updateCart();
}

Why it is vulnerable: Only zero is rejected, so -5 passes the check and is subtracted from the cart.

04. Why Does It Matter?

Accepting negative quantities can reduce the cart total, manipulate inventory calculations, and potentially cause financial losses for an online store.

MITRE provides a shopping cart example where an application calculates the total without checking whether the quantity is negative. An attacker could receive an account credit instead of being charged.

05. The Fix

Accept only positive whole numbers. In real applications, the same check must also run on the server, not only in the browser. 

function addToCart() {
    const inputValue = quantityInput.value.trim();
    const quantity = Number(inputValue);

    if (inputValue === "" || !Number.isInteger(quantity)) return;
    if (quantity <= 0) return;

    cartQuantity += quantity;
    updateCart();
}

Why it works: Zero and negative quantities are rejected, so the same payloads can no longer lower the total.
