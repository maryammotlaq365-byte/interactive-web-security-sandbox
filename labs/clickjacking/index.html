INTERACTIVE SECURITY LAB 01

Clickjacking

Learn how attackers trick users into clicking hidden elements on a website without their knowledge.

01. What is Clickjacking?

Clickjacking hides a real page inside an invisible frame on top of a harmless-looking page. The visitor thinks they click a normal button, but they actually click a button on the hidden page.

OWASP: A05:2021 – Security Misconfiguration

CWE: CWE-1021 – Improper Restriction of Rendered UI Layers or Frames

02. The Vulnerable Code

This is the server response of a sensitive page. 

HTTP/1.1 200 OK
Content-Type: text/html
# NO frame-ancestors / X-Frame-Options header

<html>
  <body>
    <button>Confirm Account Action</button>
  </body>
</html>

Why it is vulnerable: No header tells the browser who may embed this page, so any website can load it inside an invisible iframe.

04. Why Does It Matter?

An attacker can make a user change settings, approve actions, or confirm transactions without knowing it.

Real incident: In February 2009, a page with a "Don't Click" button spread across Twitter. Behind the button was a transparent Twitter iframe, so each click posted the same link on the visitor's own account.

05. The Fix

The server tells the browser that no other website may embed this page. 

HTTP/1.1 200 OK
Content-Type: text/html
Content-Security-Policy: frame-ancestors 'none'
X-Frame-Options: DENY

<html>
  <body>
    <button>Confirm Account Action</button>
  </body>
</html>

Why it works: The browser refuses to render the page inside any frame, so the hidden iframe stays empty and the click does nothing. X-Frame-Options is the older header for the same job.
